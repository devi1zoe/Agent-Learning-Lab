# 按证据链查词，不按词表背诵

| 词 | 在本课程中的精确定义 | 常见误解 |
| --- | --- | --- |
| API request / response | 发给服务的请求与原始返回 | 响应成功就是任务成功 |
| messages / context | 当前一次模型调用实际收到的信息 | 磁盘上保存的所有内容模型都会看到 |
| tool schema | 告诉模型可请求的名称、参数和用途 | schema 自己执行函数或批准写入 |
| tool call | 模型提出的结构化动作请求 | 模型已经把动作做完 |
| dispatcher / executor | 找工具并校验 / 真正调用函数 | 二者必须是不同服务 |
| observation | 环境实际返回的文本、结构或错误 | 模型自己写的“我看到了” |
| workflow | 开发者预定控制路径 | 只要使用 LLM 就是 Agent |
| agent loop | 新观察影响后续动作的重复决策过程 | 只要循环次数多就是自主 |
| ReAct | 把推理决策与外部动作反馈结合的方式 | 必须输出完整私有思维链 |
| Self-Ask | 按中间事实依赖提出子问题 | 任意把一题拆成更多调用 |
| chunk / overlap / offset | 文本块 / 重叠 / 原文起止位置 | 任意切割都不会损伤证据 |
| embedding | 在指定模型空间中的数值表示 | 相似度就是可信度或支持性 |
| retrieve / top-k | 召回候选 / 最多返回数量 | 必须凑够 k 个，即便都不相关 |
| citation | 结论到可定位来源的绑定 | 有合法编号就证明结论真实 |
| verified（本地实现字段） | 本轮非空正文已经成功读取 | 网页内容已事实核查 |
| session memory | 为后续对话恢复的历史状态 | 自动包含全部工具证据 |
| long-term memory | 跨会话持久信息及其写入/检索/删除机制 | 模型参数知识或无限完整历史 |
| prefetch | 程序事先安排的取证 | 模型主动选择的工具调用 |
| trace | 原始请求、响应、执行及回传的关联记录 | 只有最终答案的日志 |
| replay / fake / rule policy | 为检查程序路径而提供的替身 | 真实模型能力证据 |
| ablation | 控制其他条件，拿走一项机制作对照 | 改很多参数后凭感觉比较 |
| stop_reason | 为什么终止 | 自动证明任务完成 |

每次遇到一个词，回到 [研究任务主线](01-what-is-an-agent.ipynb) 指出它对应的实际对象和失败方式。能解释数据怎样经过它，比能背定义更有用。

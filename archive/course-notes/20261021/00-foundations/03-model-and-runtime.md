# 模型能力与运行时能力怎样共同决定结果

模型负责根据可见信息生成下一步。运行时负责把任务、工具、观察与预算拼成模型真正收到的输入，并把输出转换成受约束的执行。二者共同决定 Agent 行为。

```text
用户授权 → 运行时构造输入 → 模型生成请求
                  ↑             ↓
               新观察 ← 校验/执行器 ← 工具请求
```

同一个模型配上不同运行时会有不同结果：没有文件工具就不能读取本地；工具有但结果没回传就无法根据反馈改变；没有来源池就难区分本轮已读与历史编号；无限重试会把一次失败变成持续耗费。更强模型可以改善选择，却不能替不存在的工具执行读写。

反过来，程序校验再完善也不能保证模型选到了正确材料。合法参数可能问错问题，合法来源可能不支持结论。需要分别检查决策质量、执行正确性、证据支持与预算终止。

本课程的回放/规则模型只检验运行时线路；[真实证据](../evidence/20261020/README.md) 才反映本轮模型在具体任务上的生成。默认离线实验通过，不代表真实 Agent 研究任务通过。

阅读源码时先找四处：模型调用入口、工具执行点、工具结果进入 messages 的位置、停止/验收条件。然后再读类和函数的全部细节。

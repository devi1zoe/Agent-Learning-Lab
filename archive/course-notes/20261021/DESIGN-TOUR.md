# 沿一个研究任务看懂 Agent 的九个设计问题

目标是根据实际来源回答研究问题，而非让模型写出听起来完整的介绍。每一步都要看控制权、状态和反馈怎样变化；模型内部的隐含思维不作为可审计事实。

```text
用户目标与验收条件
      ↓
模型看到：指令 + 可用工具说明 + 已观察结果 + 剩余预算
      ↓
生成回答，或提出结构化动作请求
      ↓
运行时：参数、权限、预算、重复调用检查
      ↓
执行器与外部环境：读资料、查数据、观察网页
      ↓
成功 / 空结果 / 冲突 / 错误 → 更新状态 → 再次调用模型
      ↓
模型停止 → 独立检查证据和任务结果 → 完成 / 拒答 / 失败
```

| 阶段 | 必须回答的设计问题 | 本次可以观察的对象 |
| --- | --- | --- |
| 0 | 哪些下一步无法预先固定？动态决策值得承担多少代价？ | 主课的一页场景分析；固定检索基线与开放取证的区别 |
| 1 | 工具请求何时变成真实动作？没有观察时能否输出结论？ | 两次未调用工具的真实失败；加证据门后发生真正 read_file，但引用仍有缺口 |
| 2 | 相关片段、已读来源、支持某项结论是同一件事吗？ | 真实384维embedding、检索分数、来源映射、引用校验；预检索和模型自主检索分别归因 |
| 3 | 裸循环之外，谁管理权限、上下文、会话和终止？ | 固定上游 s02 原 loop 与本地裸 loop 的同题记录；其他阶段的能力不能归到 s02 |
| 4 | 多角色怎样改变可见信息？交接会丢失什么？ | writer/reviewer 的实际独立输入；单角色基线；循环、漂移和schema压力测试 |
| 5 | 一份能力包改变了什么行为？模板被加载就足以证明有效吗？ | 可独立加载的Skill包；6题有无Skill实验；事实与报告结构分开评分 |
| 6 | 浏览器工具给模型什么观察？页面指令能否改变行动权限？ | 公开网页实际DOM、截图、工具调用、摘要与逐字引文；固定恢复不能冒充自主重规划 |
| 7 | 一次“有输出”怎样拆成可定位的成功或失败？ | 20题期望/实际/分类；解析、事实、引用、任务与动作范围分别统计 |
| 8 | 哪些东西能交给另一环境运行？怎样拒绝未批准的副作用？ | 导出manifest、全新venv、CLI退出状态、确切内容/路径绑定的审批检查 |

## 用一个实际失败穿透这些层

[无证据门的第一次生成](evidence/20261020/stage1-tool-loop.json)给出了Stage 3和`[L1]`，但记录里没有任何工具事件。正确要求在上游Stage 7。模型既没有读取证据，也没有成功完成任务；`model_stopped`只是停止信号。

[加强提示](evidence/20261020/stage1-guided-tool-loop.json)仍没有让这个小模型读取文件。这说明“请使用工具”和可观察的执行约束不同。加入[运行时证据门](evidence/20261020/stage1-evidence-gate.json)后，第一次无来源回答被拒绝，随后模型提出read_file请求、程序实际读取course.md，下一轮答对Stage 7；答案却漏了引用标记。已读、答对、引用完整是三个不同的检查。

这组对照改变了运行时约束，是设计消融示例，不能混成同一协议下的模型成功率。早期日志的请求快照引用缺陷已修复，原件另存，修复后同题重跑有完整来源说明。更多原始证据和成本归因见[本轮实验说明](evidence/20261020/README.md)。

## 读源码时的顺序

先看用户目标进入哪一个messages，再定位模型调用、工具分发、工具结果回写和每个提前退出点；随后追踪来源池、会话、权限和预算。读到一个控制点时问：删掉它会允许什么可观察错误？它能否独立验证模型的声明？

代码折叠只是阅读组织，不会增加能力。主课给出设计解释，附录保留可运行实现，实验页保存真实模型输出；三者互相核对才构成学习证据。
